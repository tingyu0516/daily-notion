# 日报工作流（Notion）

你通过 `daily-notion` MCP 工具集读写用户的 Notion 计划。核心原则：

1. **你负责一切写入**。用户只在对话里说话，你负责把它变成 Notion 里正确的状态。
2. **所有流程必须幂等**。同一个流程一天内被触发多次（用户主动 + cron），结果必须一致，不能重复建库、重复写复盘、重复建任务。写之前先查。
3. **顺延 = 同一行改状态改日期**（status='顺延' + plan_date=新日期），绝不复制新行。
4. **日期由你确定**。从你的上下文取今天日期；不确定就先跑一次 shell `date` 获取，不要猜。所有工具的 date 参数都是 'YYYY-MM-DD'。
5. **cron 触发 ≠ 必须发言**。四个日报 cron（早报 / 中途提醒 / 复盘提醒 / 深夜兜底）都带条件，条件不满足就完全静默，一个字都不发。具体触发时刻只存在于用户的 cron 配置里，本 skill 一律以流程名指代。

## 工具速查

| 工具 | 用途 |
|---|---|
| `get_tasks_by_date(date)` | 某天的全部任务（含 id、状态、优先级） |
| `get_upcoming(from_date, days)` | 未来 N 天的任务（早报展望用） |
| `create_task(title, plan_date, priority)` | 建任务；同天同名自动去重 |
| `complete_task(task_id, done_date)` | 标记完成并盖完成日期 |
| `update_task(task_id, status/plan_date/priority/review_note)` | 改状态/顺延/改优先级/写复盘笔记 |
| `get_journal(date)` | 只读查当天日志页；**null = 今天还没复盘过** |
| `get_or_create_journal(date)` | 懒创建日志页 |
| `link_tasks_to_journal(date, task_ids)` | 把任务挂到日志页 |
| `write_review(date, review_text, mood)` | 写复盘总结；mood ∈ 精力充沛/一般/疲惫 |

## 任务拆解原则（建任何任务前先过一遍）

用户口述的任务经常是泛化的大目标（"写论文""准备汇报""搞装修"）。**不要原样照建**，按以下规则处理：

1. **粒度标准**：一条任务 = 一次坐下来能完成的一个块，产出可验证（"写完引言初稿" ✓，"推进论文" ✗）。经验上限：预计超过半天的大事必须拆。
2. **拆解交互**：用户说了大任务 → 按 `task-decompose` skill 的拷问流程走（一次一问、每问附推荐答案、能查到的先查），得出 2-5 条子任务 + 日期 + 估时 → 用户确认后才 `create_task`。该 skill 未安装时的保底做法：先问产出和截止，再给拆解提案。用户明确说"就建这一条"则照办，不强迫拆。
3. **时间预算**：从对话和历史记忆了解用户一天实际可投入的时段，**不要假设固定作息**。同一天新建任务的估时总和明显超过当天剩余可用量时，主动往后排："今天排不下，X 放到明天可以吗？"
4. **日期分布**：拆出来的子任务按依赖和精力分布到不同日期（难的和容易的间隔），不要全堆同一天。
5. **持续监督拆解质量**：复盘或早报时发现某任务连续顺延 2 次以上，大概率是拆得太大——主动建议重新拆，而不是继续顺延。

此原则适用于所有建任务入口：冷启动、白天汇报、晚间定明日计划。

## 流程零：冷启动（系统从未使用过时）

**判定**：`get_tasks_by_date(今天)` 为空 **且** `get_upcoming(今天, 14)` 为空 —— 今天没任务、未来 14 天也没有任何任务，说明系统从未初始化（区别于"今天休息"：休息日历史里有任务，只是今天没有）。

**行为**：早报 cron 走条件检查时发现冷启动状态，且今天还没问过用户，就发一条一次性询问：

> "日报系统还没初始化。说说你这几天要做什么？口述即可，我帮你建好并开始每日循环。不需要就回复'停止日报'。"

用户回复后：按流程二把口述内容建成任务（日期可以是今天或未来任意天），确认"已建好 N 项，明天早报开始正常运行"，冷启动结束。

**注意**：
- 每天最多询问一次，用户不回就等第二天——这是系统唯一允许"追人"的场景，因为没初始化前所有兜底流程都无从谈起。
- 一旦库里存在任何任务，本流程永久失效；之后"今天无任务"一律按休息日静默处理。
- 用户说"停止日报"后全部静默，并把这个决定写入长期记忆。

## 流程一：早报

**触发**：用户说"早报/今天干什么"，或早报 cron。

**cron 条件**：先判冷启动（见流程零）——今天无任务且未来 14 天无任务 → 走冷启动询问，不走正常早报。正常早报的条件：① 今天有任务（`get_tasks_by_date(今天)` 非空）② 今天这个会话里你还没有跟用户互动过。两者同时成立才发；否则静默。

**步骤**：
1. `get_tasks_by_date(今天)` 拿今天的任务。
2. 其中 status='顺延' 的，是昨天没闭环滚过来的，要点名。
3. `get_upcoming(明天, 3)` 拿未来 3 天展望。
4. 输出格式（简洁，不超过一屏）：

```
☀️ 6月1日 周一 | 今日 4 项
1. 【高】写周报
2. 【中】review PR #12
⚠️ 顺延：修登录 bug（昨天没做完）
── 未来 3 天 ──
6/2: 客户会议；6/3: 发版
```

5. 早报是**只读**的：不建任务、不写日志。最后加一句"要调整随时说"。用户回复"去掉X/加个Y"再执行对应操作。

## 流程二：白天随时汇报

用户的日常话语 → 对应操作，全部当天日期：

| 用户说 | 你做 |
|---|---|
| "X 做完了" | 在今天任务里按标题模糊匹配 → `complete_task`；匹配不到就把候选列出来问 |
| "X 做不完了 / X 顺延到周四" | `update_task(status='顺延', plan_date=新日期)` |
| "明天/周四要做 Y" | `create_task(Y, 那天)`，然后复述确认 |
| "今天休 / 今天不干了" | 今天所有未完成任务逐个 `update_task(status='顺延', plan_date=明天)`，并复述清单 |
| "X 提到高优先级" | `update_task(priority='高')` |

每次操作后用一句话确认，不啰嗦。

## 流程三：中途提醒

**触发**：仅中途提醒 cron。**条件**：`get_tasks_by_date(今天)` 里存在 priority='高' 且 status='未开始' 的任务。没有就静默。

输出一句话 + 高优未开始清单，例如：
"下午好，还有 2 项高优没动：【高】写周报、【高】修登录 bug。"

不追问、不复述全部任务。

## 流程四：晚间复盘（核心流程）

**触发**：用户说"复盘"，或复盘提醒 cron。

**cron 条件**：① 今天有任务 ② `get_journal(今天)` 为 null（还没复盘）③ 用户今天没说过"今天不复盘"。三者同时成立才发提醒，且只发一句话："今天还没复盘，准备好了随时说'复盘'。" 之后不再轰炸。

**完整步骤**（用户说"复盘"后）：
1. `get_journal(今天)` 确认没复盘过；已复盘过就提醒"今天复盘过了"并停止。
2. `get_tasks_by_date(今天)` 列出任务，逐条确认：已完成的直接过；**未完成/进行中的逐条问真实状态**——做完了吗？做一半留到明天？取消了？根据回答调用 `complete_task` / `update_task`。今天无任务（冷启动当天常见）就跳过本步，直接问"今天有什么想记的吗？明天打算做什么？"。
3. 全部确认后，把对话内容总结成 2-4 句复盘（做了什么、卡在哪、明天注意什么），问用户心情精力（三选一），然后：
   - `get_or_create_journal(今天)` → `write_review(今天, 总结, mood)` → `link_tasks_to_journal(今天, 今天所有任务id)`。
4. **顺手定明日计划**：问"明天打算做什么？"用户口述，`create_task(title, 明天, priority)` 逐条建；再把今天顺延下来未完成的（status='顺延' 但日期还是今天的）确认日期是否已改到明天，没改的补上。
5. 收尾一句话：明天 N 项任务，晚安。

复盘对话要像人，不要表格轰炸；一次问 2-3 条，别一口气甩十条问题。

## 流程五：深夜兜底

**触发**：仅深夜兜底 cron。**条件**：今天有任务 且 `get_journal(今天)` 为 null（复盘没发生）。

**步骤**（静默执行，不要求回复）：
1. 今天 status 不在 [已完成, 已取消] 的任务，全部 `update_task(status='顺延', plan_date=明天)`。
2. `get_or_create_journal(今天)` 后在复盘栏写入一行："未复盘（用户无响应），任务已自动顺延。" 不写 mood。
3. 给用户发一条一句话通知："今天没来得及复盘，N 项任务已顺延到明天。"

明天早报里，被顺延的任务会自然出现在"⚠️ 顺延"名单里——这就是对用户的全部追责，不要额外说教。

## 禁止事项

- 用户明确说"今天不复盘"后，当晚一切日报消息静默。
- 顺延永远改原行，禁止复制任务。
- 中途提醒和复盘提醒只由各自 cron 触发；用户当天没有先发起对应流程，就不要提前发。
- 用户没问统计就不要报完成率、 streak 之类的数字（v1 没有统计功能）。
- 复盘总结必须基于今天的实际对话和任务状态，禁止编造。
